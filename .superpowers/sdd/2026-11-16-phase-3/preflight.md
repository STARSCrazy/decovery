## C. What a code reviewer would flag as a defect (if built as mandated)

1. `run_record_matches_schema` (T6): without a validator it either asserts nothing or grows an ad-hoc validator — specify the shallow `required`-walk (B/T6).
2. `lookup_of_10000_members_is_fast` (T13): wall-clock assertion with a release-only threshold in a debug test run.
3. `affected_outputs_are_written_in_parallel_with_same_bytes` (T14): "in parallel" is not observable; the test can only assert equal bytes — rename to `parallel_output_writing_gives_same_bytes`.
4. `bench_copy_has_no_exemplar_entry_of_the_function` + `remove_exemplar` (T13): a hook removing an entry from a file that is never copied — dead code (P15).
5. `copy_contains_no_trace_of_the_solution` (T5): as worded it cannot pass on a real copy; the implementer will quietly narrow it. Name the exclusions in the plan (B/T5).
6. Duplicated logic: "distance/better" exists as `better()` in `legacy.rs`; T1 adds `attempt_distance`, T6 computes `best_distance` again. One function in core, used by all three.
7. Two attempt-counting rules (budget in T1, build limit in T6 from the call log, plus T11's "counts when recorded") — three counters for "builds". Define once (P8, P19).
8. Every full build writing 650 attempt lines and archiving every identical function (P5, B/T3): unbounded cache growth and extra I/O inside the throughput path Task 14 measures.
9. `every_mcp_call_is_logged` in a facade test file that cannot reach the MCP layer (B/T3).
