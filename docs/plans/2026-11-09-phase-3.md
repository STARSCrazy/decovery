# decovery phase 3 — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** decovery measures and raises agent effectiveness: every build attempt is remembered (attempt memory,
attempt archive, `history`), long operations run as persistent jobs (`job`), solved functions serve as exemplars
(`show`, `find similar`), and `decovery bench` runs an external agent driver on a suite of solved functions and
reports success rate, builds, tool calls, tokens and cost reproducibly. A full build uses the machine.

**Architecture:** `decovery-core` gains the attempt store (append-only JSONL shards per function), the
content-addressed attempt archive and the persistent job store. `decovery-diff` gains the similarity algorithms
(normalised instruction forms, MinHash/LSH prefilter, Decomp's coverage + Indel ranking). `decovery-facade` records
attempts in `build`, runs jobs on a job runner, keeps the exemplar index in `cache/exemplars/` and gets the tools
`history` and `job`, `find {what: similar}` and exemplars plus the current rebuild source in `show`. A new crate
`decovery-bench` holds suites, the workspace copy with the solution removed, the driver contract, run records and
statistics; the CLI gets `decovery bench run|report|compare`. The reference driver is a Python stdlib script around
Claude Code in headless mode (`tools/bench-drivers/claude_code.py`); decovery never embeds a model.

**Tech Stack:** Rust stable (edition 2024), crates per ADR 0003 (no new dependency); Python ≥ 3.12 stdlib for the
reference driver and the measurement script; Claude Code CLI ≥ 2.1 (`claude -p --bare`) for the reference driver.

**Spec:** `docs/design/0001-decovery-design.md` — section 4 (Attempt, Job, Verdict), 5.4 (`history`, `job`, `detail`,
`status`), 5.5 (`cache/`), 5.6 (`migrate` of logbook and attempt archive), 5.12 (items 1 and 2), 5.13, phase row 3
in section 7. Decomp oracle (`Decomp/src/decomp/nachbau/`): `versuche.py` (attempt memory, budget rule),
`versuchsarchiv.py` (archive format, path rules, rename retry), `versuchsherkunft.py` (compiler fingerprint),
`vorbilder.py` (exemplar ranking); `dienst.py` `_bau_merken` (~1288–1335), `nachbau_probieren` (~3698–3854),
`_vorbilder` (~5442), `nachbau_vorbilder` (5471).

## Decisions taken in this plan (deviations from the design are marked)

1. **Attempt memory is the phase-3 logbook.** Decomp has two stores: attempt memory (`versuche.jsonl` + archive) and
   a method logbook (`logbuch.sqlite`: method runs, seeds, planning of the night chain). The method logbook only
   serves search methods, which arrive in phase 4; it moves there. Decomp's compile-result cache (`fassungen`) is
   decovery's object cache already.
2. **No SQLite (ADR 0003).** Attempts are append-only JSON Lines, one shard per function
   (`cache/attempts/<address-key>.jsonl`), so `history` reads only one function's lines and a migrated memory of
   tens of thousands of attempts needs no index.
3. **Exemplars (deviation, design 5.12 item 2 amended in Task 8):** the MinHash/LSH index of the design is the
   prefilter; the ranking is Decomp's (`vorbilder.py`): window coverage plus Indel similarity, shared stretches and
   twins. The feature list of the design (size class, call/global/string counts, rule ids) is dropped: Decomp's
   ranking over normalised instruction forms is the proven oracle. The opt-in user-level library over the author's
   other workspaces moves to phase 4. Exemplars appear in `show`'s response, never in
   the generated `output/` files (they change with every newly solved function).
4. **Scheduler (deviation, design 5.13 amended in Task 6):** phase 3 builds the persistent jobs and keeps the
   existing global job slots (`--jobs`) for runner work and rayon for CPU work. The DAG executor over units moves to
   phase 4, where `search` is its first user.
5. **Throughput criterion (deviation, needs the owner's confirmation before Task 9 ends):** "a full build keeps
   ≥ 90 % of the cores busy" cannot hold on the first target: the cold build has 32 compile jobs of very unequal
   length on 16 logical cores, and its lower bound is the longest compile, not CPU ÷ cores (phase 2: 34 s CPU,
   4.2 s wall, about 51 % busy; the critical path alone is about 3 s). Phase 3 measures and reaches instead:
   **saturation ≥ 0.90** (while at least as many compile jobs are runnable as there are slots, the slots are busy)
   **and efficiency ≥ 0.85** (wall time ≤ lower bound ÷ 0.85, lower bound = max(longest job + serial phases,
   job CPU ÷ slots + serial phases)). The literal busy-core share is recorded too.
6. **Benchmark suites (deviation):** phase 3 uses private suites over the two local targets. The public suite from
   project-compiled Open Watcom / Turbo C fixtures needs a free compiler in CI and moves to phase 7.
7. **Reference driver:** Claude Code headless (`claude -p --bare --strict-mcp-config`). The agent works only through
   decovery's MCP tools (no file tools); it submits function sources with `build {variants}`; the harness takes the
   best identical attempt from the copy's attempt archive. A driver that edits `src/` itself is supported too: the
   final build sees its edits.
8. **New crate `decovery-bench`** (design section 6 amended in Task 10) and **ADR 0007** (benchmark driver contract,
   Task 11), **ADR 0008** (persistent jobs, Task 5).

## Global Constraints

- Everything English: identifiers, CLI verbs/flags, MCP tool and parameter names, file names, TOML/JSON keys, enum
  values, messages. Free texts written by people stay as they are.
- Fixed dependencies only (ADR 0003): `iced-x86`, `serde`, `toml`, `serde_json`, `clap`, `rmcp`, `tokio`,
  `tracing`, `rayon`, `blake3`, `sha2`, `thiserror`; `tempfile` for tests. No new crate dependency (no SQLite, no
  statistics or hashing crate: Wilson/Newcombe intervals, bootstrap PRNG (splitmix64), MinHash and LCS are written
  out). `unsafe_code = "forbid"` stays.
- No proprietary data in the repo: no target bytes, no private function names, addresses, sizes or hashes, no
  private suites or run records. Public tests use hand-built bytes, fake runner plugins and a fake driver. Local tests
  are `#[ignore = "local: …"]` and read `DECOVERY_LOCAL_WORKSPACE`, `DECOVERY_LOCAL_WORKSPACE_MZ`,
  `DECOVERY_TARGET_MZ`, `DECOVERY_TOOLCHAIN_WATCOM95`, `DECOVERY_TOOLCHAIN_TC20`, `DECOVERY_GOLDEN_DIR`,
  `DECOVERY_PYTHON`, and new `DECOVERY_DECOMP` (path of Decomp's `decomp.cmd`, Task 4 and 8 only).
- Every on-disk record carries `schema = 1` (JSON: `"schema": 1`); writes are atomic (`write_atomic`) or single
  appends under a lock; unknown keys in records decovery rewrites are preserved (`#[serde(flatten)] extra`).
- Public enums/structs `#[non_exhaustive]`; serialized enum values are kebab-case ids; library code never panics
  on input data; malformed input names the file and line or byte offset.
- Verdicts are set only by decovery (design 4): a bench task is solved only by decovery's verdict on the copy.
- Times on disk: RFC 3339 UTC to the second (`2026-11-10T08:15:02Z`), written by one helper `now_utc()` next to
  `today()` in `decovery-core`.
- Each task ends green on `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo test --workspace` (run without `DECOVERY_PYTHON` set; `runner_synthetic` maps an absolute Python path) and
  `python -m unittest discover -s tests` in each touched Python directory, then one commit with a conventional
  message and the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Stage files explicitly; LF
  line endings. No push.

## Review Focus

1. **A bench copy leaks the solution** — `.git/`, `output/`, `cache/handles/`, the kept object of the function's
   file, the object cache, staged run directories, the rebuild record, attempt shards and archive entries of the
   function, the exemplar entry. Expected: none of the function's original definition text (whitespace-normalised)
   and none of its compiled bytes occur in any file of the copy. Owner: Task 10
   (`copy_contains_no_trace_of_the_solution`).
2. **A driver hangs, crashes or overspends** — the harness kills the driver's process tree at the wall limit,
   records `exit = "timeout"` / `"driver-error"`, evaluates the copy anyway and continues with the next task; MCP
   tools refuse further builds/calls once the budget is spent ("budget exhausted: 40 of 40 builds used"). Owner:
   Task 11 (`hanging_driver_is_killed_and_evaluated`, `crashing_driver_is_recorded`,
   `tool_calls_beyond_budget_are_refused`).
3. **Two writers append attempts at once** (a CLI build while an MCP job builds) — every line survives; a torn last
   line from a crash is skipped with a warning naming file and line. Owner: Task 1
   (`concurrent_appends_keep_every_line`, `torn_last_line_is_skipped`).
4. **The MCP server dies while a job runs** — on the next start the job is re-queued once from its spec (units come
   from the cache) and ends `interrupted` after a second loss; a cancelled build writes no records, no kept objects
   and no output. Owner: Task 5 (`cancelled_build_writes_nothing`), Task 6
   (`restart_requeues_running_job_once`).
5. **Exemplars on a fresh or changed workspace** — no identical function: `find similar` returns an empty list with
   the hint "no solved functions to compare with"; the target's sha256 changed: the index is rebuilt; a function is
   never its own exemplar; an assembler-file function is never an exemplar. Owner: Task 8
   (`empty_index_gives_hint`, `changed_target_rebuilds_index`, `function_is_not_its_own_exemplar`,
   `assembler_functions_are_not_exemplars`).

  ```rust

  pub fn now_utc() -> String;                         // RFC 3339 UTC, seconds
  #[non_exhaustive] pub enum AttemptOrigin { Build, Variant, Function, Bench, Migrate }   // ids build, variant, function, bench, migrate
  #[non_exhaustive] pub struct AttemptRecord {
      pub schema: u32, pub time: String, pub address: Address, pub name: String, pub file: Option<String>,
      pub origin: AttemptOrigin, pub label: Option<String>, pub actor: Option<String>,   // cli | mcp | bench:<run-id> | migrate
      pub profile: String, pub flags: String,
      pub body_hash: String,     // blake3 hex of the function's definition text, LF line ends
      pub context_hash: String,  // blake3 hex over the rest of the file, the headers and the tool fingerprint
      pub original_hash: String, // blake3 hex of the original function bytes
      pub result: RebuildResult, pub verdict: Option<VerdictId>,
      pub instructions_differing: Option<u32>, pub bytes_differing: Option<u32>,
      pub blockers: Vec<String>, pub diagnosis: Vec<String>, pub archive: Option<String>,
      #[serde(flatten)] pub extra: serde_json::Map<String, serde_json::Value> }
  pub fn append_attempts(root: &Path, records: &[AttemptRecord]) -> Result<(), WorkspaceError>;
  pub fn read_attempts(root: &Path, address: Address) -> Result<(Vec<AttemptRecord>, Vec<String> /*warnings*/), WorkspaceError>;
  pub fn attempt_distance(r: &AttemptRecord) -> Option<u64>;   // 0 identical; instructions_differing; None for error
  #[non_exhaustive] pub struct AttemptBudget { pub own: u32, pub since_progress: u32, pub best: Option<u64>, pub limit: u32 }
  impl AttemptBudget { pub fn parked(&self) -> bool }           // best != Some(0) && since_progress >= limit
  pub fn attempt_budget(records: &[AttemptRecord], limit: u32) -> AttemptBudget;
  pub const DEFAULT_ATTEMPT_BUDGET: u32 = 30;
  ```
- Shard name: the address text with `:` replaced by `_` plus `.jsonl` (`flat_00012340.jsonl`,

  wait 10 s) and write each shard's new lines in one `write_all`. Records are read oldest first.
- Budget rule (port of `versuche.budget`): counted are records with origin `build`, `variant` or `function`, result
  not `error`, each `body_hash` once, oldest to newest; a new best distance resets `since_progress` to 0, otherwise
  it grows by 1. `limit` comes from `[rebuild] attempt_budget` (default 30).

  pub const WINDOW: usize = 6;  pub const HASHES: usize = 64;  pub const BANDS: usize = 16;  pub const PRESELECT: usize = 30;
  pub fn minhash(forms: &[u32]) -> [u64; HASHES];                // over WINDOW-grams; shorter sequences: one gram
  pub fn lsh_keys(sketch: &[u64; HASHES]) -> [u64; BANDS];       // 4 rows per band
  pub fn coverage(target: &[u32], candidate: &[u32]) -> f64;     // Decomp abdeckung
  pub fn indel_similarity(a: &[u32], b: &[u32]) -> f64;          // 2·LCS / (|a|+|b|), 1.0 for two empty
  pub fn shared_stretches(target: &[u32], candidate: &[u32]) -> Vec<Stretch>;   // top 3, longest first
  #[non_exhaustive] pub struct Stretch { pub target: (usize, usize), pub candidate: (usize, usize) }
  #[non_exhaustive] pub struct Ranked { pub candidate: usize, pub similarity: f64, pub coverage: f64, pub score: f64,
      pub stretches: Vec<Stretch>, pub twin: bool }
  pub fn rank(target: &[u32], target_coarse: &[u32], candidates: &[(&[u32], &[u32])], top: usize) -> Vec<Ranked>;

- Normalisation (port of `vorbilder.py`, on iced-x86 Intel text): mnemonic + operands; hex and decimal numbers → `N`;
  `eax|ebx|ecx|edx|esi|edi` → `r`, `ax|bx|cx|dx|si|di` → `r16`, `al|ah|bl|bh|cl|ch|dl|dh` → `r8`; `ebp`, `esp`, `bp`,
  `sp` kept. Forms are interned to `u32` by the caller (Task 8 keeps the table).
- `coverage`: n = min(WINDOW, |target|); target windows = all n-grams; covered target positions are those inside any
  window that also occurs in the candidate; result = covered ÷ (windows + n − 1); 0 when the candidate is shorter than
  n. `rank`: preselect by (coverage, −|len difference|) descending, keep `max(PRESELECT, top)`, then
  `similarity = indel_similarity` rounded to 3 decimals, `score = (similarity + coverage) / 2`, descending, ties by
  candidate index; `twin` = coarse sequences equal. Stretches as Decomp `_strecken` (greedy from the front, longest
  continuation among candidate positions starting the same window).
- MinHash: hash i of a gram = splitmix64(gram_hash ⊕ seed_i), seeds = splitmix64 sequence from 0x6465636f76657279;
  gram_hash = blake3 of the gram's u32 values (first 8 bytes).
