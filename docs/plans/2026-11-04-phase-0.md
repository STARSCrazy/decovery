# decovery phase 0 — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A buildable, publishable Rust workspace that loads Watcom LE executables and OMF objects, compares a
rebuilt function with the original exactly like Decomp does, migrates a Decomp workspace, and talks to
out-of-process plugins (Python SDK + Ghidra plugin skeleton).

**Architecture:** Cargo workspace under `crates/`; core types in `decovery-core`, format readers in
`decovery-loaders` / `decovery-objects`, x86 decoding in `decovery-x86` (iced-x86), comparison in
`decovery-diff`, plugin protocol in `decovery-plugin`, binary in `decovery-cli`. Python plugins under `plugins/`.
Ports of Decomp modules keep Decomp's semantics; Decomp is the oracle.

**Tech Stack:** Rust stable (rustc 1.99.1, edition 2024), iced-x86, serde, toml, serde_json, clap, thiserror,
blake3; Python ≥ 3.12 stdlib only for the SDK; pyghidra for the Ghidra plugin.

**Spec:** `docs/design/0001-decovery-design.md`

## Global Constraints

- Everything English: identifiers, CLI verbs/flags, file names, TOML keys, enum values, messages, docs.
- Licence `Apache-2.0 OR MIT`; fixed dependencies only: `iced-x86` plus general-purpose crates (`serde`, `toml`,
  `serde_json`, `clap`, `rmcp`, `tracing`, `rayon`, `blake3`, `thiserror`). Anything else needs an ADR.
- No unicorn, no GPL code linked. No proprietary data in the repo (no game binaries, compiler files, decompiled
  game code, golden data derived from them). Public tests use synthetic bytes built inside the test.
- Tests that need private data are `#[ignore = "local: …"]` and read paths from env vars:
  `DECOVERY_LOCAL_WORKSPACE` (a private Decomp workspace) and `DECOVERY_GOLDEN_DIR` (reference data exported by
  `tools/golden/`, kept outside the repository). Run with `cargo test -- --ignored`.
- Library code never panics on input data: malformed input returns `Err` with the byte offset.
- Address text forms (canonical, lowercase prefix, uppercase hex): `flat:0001A2B0`, `seg:1234:0010`,
  `sel:0007:00001234` (static segment number); input-only `file:0x1A2B`; `flat64:` reserved.
- Every on-disk file carries `schema = 1`. Public enums/structs are `#[non_exhaustive]`; serialized enum values
  are kebab-case string ids. Enum variants are added together with the code that produces them.
- Interface decisions from the review are in design section 5.11; they override older sections.
- Commit after every task with a conventional message and the trailer
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Stage files explicitly (never `git add -A`). No push.
- Windows paths may contain spaces and non-ASCII (e.g. a user profile such as `C:\Users\Jürgen Müller`); never build paths by string
  concatenation.

## Review Focus

1. Truncated or corrupt LE/OMF input (cut at any offset) → `Err` naming the offset, never a panic. Owner: Tasks 4, 5
   (fuzz-style truncation tests).
2. LE fixup whose target field straddles a page boundary → applied identically to Decomp. Owner: Task 4.
3. OMF `LIDATA` (iterated data) and `FIXUPP` thread subrecords → same bytes and relocations as Decomp's reader.
   Owner: Task 5.
4. Function that is last in its segment / has no following public → length and relocations identical to Decomp.
   Owner: Task 6.
5. `migrate` meets a key or value it cannot map → listed in the migration report, never silently dropped.
   Owner: Task 7.

### Task 9: Plugin protocol, host and Python SDK

**Files:**

**Interfaces:**
- Protocol (design 5.1 + 5.11 item 4): JSON-RPC 2.0, one JSON object per line, stderr = logs, requests host →
  plugin only. `initialize {protocol: "decovery-plugin/1", host_version}` →
  `{name, version, protocol, capabilities: {"<cap>": {"version": <u32>}}}`; `shutdown` → `null`; notifications
  `$/cancel {id}` (host → plugin) and `$/progress {id, done, total?, message?}` (plugin → host). Methods
  `<capability>/<op>`. Errors: `-32601` unknown method, `-32001` capability not supported, `-32002` cancelled.
  Blobs: `{"inline_base64": …}` below 64 KiB, else `{"blob": {"path": "<abs>", "blake3": "<hex>"}}`.
- Rust:
  ```rust
  pub struct PluginHost { /* child, writer, reader thread routing responses by id */ }
  impl PluginHost { pub fn spawn(command: &[OsString], cwd: &Path) -> Result<Self, PluginError>;
                    pub fn info(&self) -> &PluginInfo;
                    pub fn call(&self, method: &str, params: serde_json::Value, options: CallOptions<'_>) -> Result<serde_json::Value, PluginError>;
                    pub fn shutdown(self) -> Result<(), PluginError>; }
  pub struct CallOptions<'a> { pub timeout: Duration, pub cancel: Option<CancelToken>, pub on_progress: Option<&'a (dyn Fn(Progress) + Sync)> }
  #[derive(Clone)] pub struct CancelToken(Arc<AtomicBool>);  impl CancelToken { pub fn new() -> Self; pub fn cancel(&self); }
  pub struct Progress { pub done: u64, pub total: Option<u64>, pub message: Option<String> }
  pub struct PluginInfo { pub name: String, pub version: String, pub protocol: String, pub capabilities: BTreeMap<String, u32> }
  #[non_exhaustive] pub enum PluginError { Spawn(std::io::Error), Protocol(String), Timeout, Cancelled, Remote { code: i64, message: String }, Exited }
  ```
  `call` takes `&self` (overlapping calls from several threads); on timeout or cancel it sends `$/cancel` and
  discards the late response.
- Python: `decovery_plugin.Plugin(name, version)`; `@plugin.method("analyzer/functions", capability_version=1)`;
  handler `(params: dict, ctx) -> Any` with `ctx.progress(done, total=None, message=None)` and `ctx.cancelled`;
  `plugin.serve()` is a blocking stdio loop, handlers run in worker threads so `$/cancel` is seen; stdlib only.
