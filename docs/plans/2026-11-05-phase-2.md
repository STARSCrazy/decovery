# decovery phase 2 — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** decovery rebuilds functions and whole programs: compiler profiles, runners that execute the original DOS
compilers (unicorn emulator, dosbox-lab, native), the facade tools `build` (with `variants[]`, the design's `try`),
`link` and `diagnose`, generic diagnosis, and an MZ/COM loader with a working 16-bit path. `build` verdicts equal
Decomp's for all identical functions of the first target (Watcom 9.5, LE) and of the second target (Turbo C 2.0, MZ).

**Architecture:** A new crate `decovery-toolchain` holds profiles (embedded TOML), tool-directory resolution, source
staging, the `Runner` contract with its providers (plugin runner, native runner, fallback chain), the object cache and
the build/link orchestration. Runners that emulate DOS are out-of-process plugins speaking capability `runner` v1:
`plugins/unicorn-dos` (Python, GPL-2, unicorn 2.1.1; Phar Lap host ported from Decomp's `emu_dos.py` plus a new
real-mode MZ host for Turbo C/TLINK) and `plugins/dosbox-lab`. `decovery-diff` gains module-level comparison with
16-bit reference anchoring (ADR 0006), instruction pairs, generic diagnosis rules and whole-program comparison
(MZ, LE). `decovery-core` gains the `rebuild.toml`/`rebuild-program.toml` writers and the user config.
The facade, CLI and MCP get `build`, `link`, `diagnose`.

**Tech Stack:** Rust stable (edition 2024), crates per ADR 0003; Python ≥ 3.12 with `unicorn==2.1.1` for the
emulator plugin; Watcom C/C++32 9.5 (`<watcom-9.5 dir>`), Turbo C 2.0 and the second target in `extern/`.

**Spec:** `docs/design/0001-decovery-design.md` (sections 4 Verdict/Attempt, 5.1, 5.2, 5.4, 5.7, 5.9 `Runner`,
5.11 items 1, 2, 7, 9, 11; phase row 2 in section 7). Decomp oracle (`Decomp/src/decomp/`):
`nachbau/compiler.py` (profiles), `nachbau/uebersetzen.py` (runner use, `_lauf`, `uebersetze_viele`, `linke`),
`nachbau/emu_dos.py` + `emu_uebersetzen.py` (emulator), `nachbau/quellen.py` (staging), `nachbau/schummel.py`
(cheat check), `nachbau/vergleich.py` + `befehle.py` (comparison, pairs), `nachbau/diagnose.py`,
`abweichungsart.py`, `einstufung.py`, `linkdiagnose.py`, `le_binden.py`, `le_vergleich.py`, `omf_schreiben.py`,
`nachbau/ergebnis.py` (records, merge), `formate/le.py` (`rohfixups`, `verarbeitungsfolge`, `kopfdaten`),
`dienst.py` (`nachbau_bauen` 1083, `_nachbau_vergleich` 1004, `nachbau_linken` 3325, `_le_einsaetze` 3431,

## Decisions taken in this plan (deviations from the design are marked)

1. **unicorn provider in Python (deviation from ADR 0004 / design 5.7, decided by the owner 2026-11-05).** No C
   toolchain is available to build the `unicorn-engine` crate; the Python wheel ships a prebuilt library. The
   provider is `plugins/unicorn-dos` (GPL-2.0, own `LICENSE`), never imported or linked by Rust. Task 7 amends
   ADR 0004 and design 5.7.
2. **Turbo C runs in the emulator too (new work).** Decomp ran TCC/TLINK only in DOSBox. dosbox-lab is not on the
   development machine, so `unicorn-dos` gets a real-mode MZ host (Task 8). dosbox-lab remains a supported runner.
3. **16-bit references are checked by anchoring (ADR 0006, Task 3).** MZ has no relocations for offsets, so the
   current rule would mark every 16-bit data reference wrong; Decomp did not check them at all.
4. **Deferred to later phases (design revised 2026-11-05 accordingly):** profile `gcc-djgpp` (needs a COFF reader
   and a DPMI host; neither target needs it) → phase 7; data-driven rules `rules/<family>.toml` (Watcom-only
   content, Python regexes with backreferences over capstone text) → phase 5 with the Watcom family;
   attempts/logbook, benchmark and exemplars → phase 3 (design 5.12).
5. **Added 2026-11-05 (owner):** function-level attempts (design 5.12 item 3) → Task 18; parallel compile and
   compare over all cores with recorded throughput (design 5.13) → Tasks 11 and 17.

## Global Constraints

- Everything English: identifiers, CLI verbs/flags, MCP tool and parameter names, file names, TOML/JSON keys, enum
  values, messages. Free texts written by people stay as they are.
- Fixed dependencies only (ADR 0003): `iced-x86`, `serde`, `toml`, `serde_json`, `clap`, `rmcp`, `tokio`,
  `tracing`, `rayon`, `blake3`, `sha2`, `thiserror`; `tempfile` for tests. No regex crate, no encoding crate (the
  CP437 table is written out). No GPL code is linked; Rust never imports `plugins/unicorn-dos`.
- No proprietary data in the repo: no compiler binaries, no target bytes, no OBJs from commercial compilers in
  fixtures. Public tests use hand-built OMF/MZ/LE bytes and fake runner plugins. Local tests are
  `#[ignore = "local: …"]` and read `DECOVERY_LOCAL_WORKSPACE` (first target's Decomp workspace),
  `DECOVERY_LOCAL_WORKSPACE_MZ` (second target's Decomp workspace), `DECOVERY_TARGET_MZ` (path of PROGRAM.EXE),
  `DECOVERY_TOOLCHAIN_WATCOM95`, `DECOVERY_TOOLCHAIN_TC20`, `DECOVERY_GOLDEN_DIR`, `DECOVERY_PYTHON`.
- Every on-disk file carries `schema = 1`; writes are atomic and deterministic; unknown keys in records that
  decovery rewrites are preserved.
- Public enums/structs `#[non_exhaustive]`; serialized enum values are kebab-case ids; variants arrive with the code
  that produces them. Library code never panics on input data; malformed input names the byte offset.
- Verdicts are set only by decovery (design 4); the facade never turns an agent's statement into a verdict.
- DOS side: build dir is drive `C:` (writable), tool dir is drive `D:` (read-only); command lines over 126
  characters are rejected before running; sources are staged as CP437 with CRLF under upper-case 8.3 names.
- Each task ends green on `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all`
  (and `python -m unittest discover -s tests` in each touched plugin), then one commit with a conventional message
  and the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Stage files explicitly. No push.

## Review Focus

1. **A compiler that hangs or crashes** → the job ends after the timeout (default 120 s, `[rebuild] timeout_s`)
   with status `timeout`; partial outputs of that job are deleted; the file's functions get `result = "error"` with
   the message; other files of the same build still complete. Owner: Task 6 (`timeout_job_is_reported`), Task 11
   (`failing_file_does_not_stop_others`).
2. **A source file with a character outside CP437, an LF-only file, or a name that is not 8.3** → converted to CRLF
   silently; non-CP437 → error "<file>:<line>: character U+XXXX does not exist in code page 437"; bad name → error
   naming the rule `[a-z0-9_-]{1,8}.(c|h|s|asm)`. Owner: Task 5 (`lf_source_is_staged_with_crlf`,
   `non_cp437_character_names_line`, `long_name_is_rejected`).
3. **Tool directory not configured or missing** → error "toolchain watcom-9.5: no tool directory; run `decovery
   setup toolchain watcom-9.5 <dir>`" (or "… directory <path> does not exist"). Owner: Task 4
   (`missing_tool_dir_names_setup_command`).
4. **A function in the OBJ without counterpart in the original** (no symbol, no default-name match) → hint
   "<name>: no counterpart in the original", no record, no error. Owner: Task 11 (`unknown_function_is_a_hint`).
5. **Building one file** keeps the records of all other files; **building all** drops records of files that no
   longer exist in `src/`; an equivalence verdict survives a rebuild with unchanged code. Owner: Task 11
   (`merge_keeps_other_files`, `build_all_drops_vanished_files`, `equivalence_survives_same_code`).

Image range as Decomp's `karte_aus_mz`: `offset = header_paragraphs*16`; `end = pages*512 - (512 - last_page_bytes
if last_page_bytes != 0 else 0)`, clamped to `[offset, file_len]`. One region `image` at `seg:0000:0000`,
`X86Real16`, rwx, `file_offset = Some(offset)`, data = image bytes unrelocated (as stored in the file).
Entry point `seg:CS:IP`. Each relocation entry `(off, seg)` becomes `Relocation { at: Seg{seg, off}, kind:
Selector, width: 2, target: Seg{seg: <word at that place>, off: 0}, addend: 0 }`; an entry outside the image is
`LoadError::Truncated`/`Unsupported` naming the file offset of the entry. Bytes behind the image set
`trailing_len` and a warning. COM: region `image` at `seg:0000:0100`, file offset 0, entry `seg:0000:0100`,
no relocations; files over 65 280 bytes are rejected.

### Task 3: Module comparison with 16-bit anchoring (ADR 0006)

**Files:**
- Create: `docs/adr/0006-16-bit-references.md`, `crates/decovery-diff/src/anchors.rs`
- Modify: `crates/decovery-diff/src/{lib.rs,compare.rs}`, `crates/decovery-facade/src/session.rs` (symbol view),
  `crates/decovery-cli/src/compare.rs` (use the facade's view)
- Test: `crates/decovery-diff/tests/module_synthetic.rs`

ADR 0006 decides, for relocated fields of 16-bit functions whose original has no relocation at that place
(MZ offsets): a field is checked against an **anchor** established by consensus over all functions of one build.
(a) Frame anchor per frame name (group or section): candidate base `linear(target) - field` from every field whose
target has a known address; `[rebuild.frames]` in `decovery.toml` overrides. (b) Section anchor per OBJ section
without a named target: candidate `field - (section_offset + addend + content)` (frame-relative). The majority
value is the anchor (tie: lowest); fields agreeing are matched, others are `WrongAbsoluteRef`. When the frame
anchor is known, the initialized bytes of an anchored data section (excluding its own fixup fields) must equal the
original at `frame + section_anchor`; otherwise every field into that section is `WrongAbsoluteRef`. Without a
frame anchor the section check is skipped and a warning says so. Selector fields compare the MZ relocation's
segment value with the frame anchor's segment. 32-bit behaviour is unchanged except that fields previously
`UncheckedRef` for unnamed other-section targets now use section anchors.

**Interfaces:**
- Consumes: `Frame`, `Group` (Task 2), `Program` relocations of MZ (Task 1).
- Produces:
  ```rust
  pub struct Placement<'a> { pub function: FunctionView<'a>, pub at: Address, pub original_len: Option<u32> }
  #[derive(Default)] pub struct ModuleOptions { pub padding: bool, pub frames: BTreeMap<String, Address> }
  #[non_exhaustive] pub enum AnchorSource { Config, Consensus }
  #[non_exhaustive] pub struct Anchor { pub frame: String, pub section: Option<String>, pub base: u64,
      pub votes: u32, pub dissent: u32, pub source: AnchorSource }
  #[non_exhaustive] pub struct ModuleComparison { pub functions: Vec<Comparison>, pub anchors: Vec<Anchor>,
      pub warnings: Vec<String> }
  pub fn compare_module(placements: &[Placement<'_>], program: &Program, symbols: &dyn SymbolView,
                        decoration: &Decoration, options: &ModuleOptions) -> ModuleComparison;
  // decovery_facade
  impl Session { pub fn symbol_view(&self) -> impl SymbolView + '_; }   // default names for Flat and Seg
  pub struct KnowledgeView<'a> { … }   // usable without analysis: KnowledgeView::new(&Workspace, Option<&Analysis>)
  ```
