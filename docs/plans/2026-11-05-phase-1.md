# decovery phase 1 — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A decovery workspace can be read, annotated and inspected like a Decomp workspace: knowledge is written
back losslessly, analysis results (functions, calls, strings, global accesses, pseudo-C) are stored in the
workspace, `output/` is generated from them, and the facade tools `status`, `find`, `show`, `annotate`,
`analyze`, `detail` work from the CLI and over MCP. `show` reproduces Decomp's `zeige` (modulo English).

**Architecture:** Knowledge writing and the analysis store live in `decovery-core`. A new crate
`decovery-facade` holds the workspace session (knowledge + analysis + program), target resolution, output
generation and the six tool operations, each returning one response envelope (`summary`, `data`, `handles`).
`decovery-cli` and a new `decovery-mcp` (rmcp, stdio) are thin front ends over the facade. Analysis comes from two
providers: `migrate` imports the analysis Decomp already generated (`provider = "decomp-import"`), and
`analyze` runs the Ghidra plugin (`provider = "ghidra"`), which gains project persistence, knowledge apply,
export and batch decompile.

**Tech Stack:** Rust stable (edition 2024), serde, toml, serde_json, clap, thiserror, blake3, rmcp; Python ≥ 3.12
and pyghidra for the Ghidra plugin; Ghidra 12.1.4 + JDK 21 installed into `extern/` by `decovery setup ghidra`.

**Spec:** `docs/design/0001-decovery-design.md` (sections 4, 5.4, 5.5, 5.11; phase row 1 in section 7).
Decomp oracle for `show`: `Decomp/src/decomp/ausgabe.py` (`kopf`, `_zeile`, `_groesse`, lists), `dienst.py`
(`zeige`, `adresse`, `_funktion`, `stand`, `funktionen`, `suche`, `querverweise`, `benenne`, `kommentiere`,
`signatur`, `lokal`, `widerlege`, `typ_hinzufuegen`, `_synchronisieren`, `_betroffene`),
`nachbau/ergebnis.py:kopfzeile`.

## Global Constraints

- Everything English: identifiers, CLI verbs/flags, MCP tool and parameter names, file names, TOML/JSON keys, enum
  values, messages, output headers. Free texts written by people (comments, evidence) stay as they are.
- Fixed dependencies only: `iced-x86` plus `serde`, `toml`, `serde_json`, `clap`, `rmcp`, `tracing`, `rayon`,
  `blake3`, `thiserror` (ADR 0003). No regex crate: `find` uses case-insensitive substring with `*` wildcard.
  HTTP downloads run through an external `curl` process. A crate rmcp's macros require as a direct dependency is
  added with a one-line amendment to ADR 0003 in the task that needs it.
- No proprietary data in the repo. Public tests build synthetic workspaces in a temp dir. Tests on private data are
  `#[ignore = "local: …"]` and read `DECOVERY_LOCAL_WORKSPACE` (a private Decomp workspace), `DECOVERY_GOLDEN_DIR`,
  and for Ghidra `GHIDRA_INSTALL_DIR` plus `DECOVERY_PYTHON` (a Python with pyghidra).
- Every on-disk file carries `schema = 1` (JSON: `"schema": 1`). Writes are atomic (write `<file>.tmp`, rename) and
  deterministic (stable order, LF line endings, UTF-8): writing unchanged data yields identical bytes.
- Public enums/structs `#[non_exhaustive]`; serialized enum values are kebab-case ids; variants arrive with the code
  that produces them. Library code never panics on input data.
- Address text forms as in phase 0 (`flat:0001A2B0`, `seg:1234:0010`, `sel:…`, input-only `file:0x1A2B`).
  Output file names use the address with `:` replaced by `_` (`flat_00010010`).
- Verdicts and claims: the facade reports tool findings; it never turns an agent's statement into a verdict.
- Each task ends green on `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all`
  (and `python -m unittest discover -s tests` in a touched plugin), then one commit with a conventional message and
  the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Stage files explicitly. No push.
- Paths may contain spaces and non-ASCII; build paths with `Path::join`.

## Review Focus

1. **A name that is not a C identifier, or a non-ASCII name** in `annotate` → rejected with a message naming the
   rule (`[A-Za-z_][A-Za-z0-9_]*`), knowledge unchanged. Owner: Task 8 (`rejects_invalid_identifier`).
2. **A target inside a function, outside any function, or outside the memory map** → inside resolves to the
   containing function; outside a function says "flat:… is in no function (nearest: <name> at …)"; outside the map
   says so. Owner: Task 4 (`resolves_address_inside_function`, `address_in_no_function_names_nearest`,
   `address_outside_map_is_rejected`).
3. **A rename** → the old output file is removed, the function's file and its callers'/callees' files are
   regenerated, no orphan files remain. Owner: Task 5 (`rename_moves_file_and_updates_callers`).
4. **Two writers at once** (CLI `annotate` while the MCP server writes) → serialized by a workspace lock file; the
   second waits up to 10 s, then fails with "workspace is locked by pid N"; TOML is never half-written.
   Owner: Task 1 (`second_writer_waits_for_lock`, `stale_lock_of_dead_process_is_taken_over`).
5. **No analysis, or analysis of another target** (sha256 differs) → `show`/`status`/`find` answer "no analysis for
   this target; run `decovery analyze`" (exit code 2), never a panic or stale data. Owner: Task 4
   (`missing_analysis_is_reported`, `analysis_of_other_target_is_rejected`).

### Task 2: Analysis store (ADR 0005)

**Files:**

ADR 0005 decides: analysis results are workspace data, committed with the workspace, in `knowledge/analysis/`:
`analysis.json` (one file) plus `decompiled/<address>.c` (pseudo-C per function, as the provider printed it).
They are replaced as a whole by `analyze` or `migrate`, never edited by hand. Rationale: design 5.11 item 8
(`status/find/show` without a running Ghidra); `cache/` is gitignored and would not reach CI or a second machine.

**Interfaces:**
- Produces:
  ```rust

      pub schema: u32,
      pub provider: Provider,                    // { name: "ghidra" | "decomp-import", version: String }
      pub target_sha256: String,                 // must equal decovery.toml target.sha256
      pub knowledge_hash: String,                // blake3 of symbols.toml + types.h + references.toml at analysis time
      pub created: String,                       // ISO date
      pub functions: Vec<AnalyzedFunction>,      // sorted by start
      pub calls: Vec<CallEdge>,                  // sorted by (site)
      pub strings: Vec<StringItem>,
      pub data_accesses: Vec<DataAccess>,
  }
  pub struct AnalyzedFunction { pub start: Address, pub end: Address /* inclusive */, pub body_size: u32,
                                pub provider_name: Option<String>, pub decompile_error: Option<String> }
  pub struct CallEdge { pub site: Address, pub caller: Address, pub callee: Address }
  pub struct StringItem { pub address: Address, pub text: String, pub users: Vec<Address> }
  pub struct DataAccess { pub function: Address, pub address: Address, pub kind: AccessKind }
  #[non_exhaustive] pub enum AccessKind { Read, Write }
  pub const ANALYSIS_DIR: &str = "knowledge/analysis";
  impl Analysis {
      pub fn load(root: &Path) -> Result<Option<Analysis>, WorkspaceError>;           // None if absent
      pub fn save(&self, root: &Path, lock: &WorkspaceLock) -> Result<(), WorkspaceError>;
      pub fn decompiled(root: &Path, start: Address) -> Result<Option<String>, WorkspaceError>;
      pub fn save_decompiled(root: &Path, start: Address, code: &str, lock: &WorkspaceLock) -> Result<(), WorkspaceError>;
      pub fn index(&self) -> AnalysisIndex<'_>;
  }
  pub struct AnalysisIndex<'a> { /* built once */ }
  impl AnalysisIndex<'_> {
      pub fn function_containing(&self, at: Address) -> Option<&AnalyzedFunction>;  // binary search on start
      pub fn function_at(&self, start: Address) -> Option<&AnalyzedFunction>;
      pub fn callers(&self, f: Address) -> &[&CallEdge];                              // by callee
      pub fn callees(&self, f: Address) -> &[&CallEdge];                              // by caller
      pub fn strings_used_by(&self, f: Address) -> Vec<&StringItem>;                  // in address order
      pub fn accesses_of(&self, f: Address) -> &[&DataAccess];                        // in stored order
  }
  pub fn knowledge_hash(root: &Path) -> Result<String, WorkspaceError>;
  ```

### Task 5: Output generation

**Files:**
- Create: `crates/decovery-facade/src/output/{mod.rs,header.rs,files.rs,indices.rs}`
- Test: inline tests (header lines), `crates/decovery-facade/tests/output_synthetic.rs`

Layout (English counterpart of Decomp's `ausgabe/`): `output/functions/<segment>/<address>_<name>.c`
(`<segment>` = configured segment name containing the start, `seg_XXXX` for real-mode `seg:` addresses),
`output/index.md`, `output/calls.json`, `output/strings.md`, `output/globals.md`, `output/status.json`. Every
generated file starts with a line stating it is generated (`.c`: inside the header is enough; `.md`: first line
`<!-- generated by decovery; do not edit -->`; JSON: `"schema": 1`).

Header format (port of `ausgabe.kopf`/`_zeile`): each line `" * " + key padded to 11 + " " + value`, continuation
lines indented the same way, the first line starts with `/* `, the header ends with ` */`, `*/` inside text becomes
`* /`. Lines in order, omitted where marked optional:

| Key | Value (Decomp source → English text) |
|---|---|
| `@address` | `<start> .. <end> (<N> bytes, file 0x<off>)`; if span ≠ body: `(<span> bytes span, <body> in body, file 0x<off>)`; `, file …` only when the start has a file offset; the offset in lowercase hex as Decomp prints it |
| `@name` | `<name>  [<source>, <confidence>]`, or `fun_…  [unnamed]`; source/confidence as kebab ids (`agent`, `human`, `signature`, `runtime`, `import`, `analysis`, `similarity`; `confirmed`, `assumed`) |
| `@signature` | optional |
| `@library` | optional |
| `@called-by` | `<address> <name>` per distinct caller, `(n×)` for several sites, max 20 then `, … (+<rest>)`, always ending `  (<total>)`; `(none)` if empty |
| `@calls` | same for callees |
| `@strings` | `<address> "<text, first 60 chars, \n escaped>"`, same list rule |
| `@globals` | `reads|writes <address> [<name>]` joined by `; `, not truncated; `(none)` |
| `@rebuild` | `not tried`; `error: <first line> (<file>, <date>)`; `identical (<file>, <compiler> <flags>, <equal> fixed + <gaps> linker[, N refs unchecked][, N padding bytes][, alignment +k][, but N instruction(s) differ (diagnosis: …)], <date>)`; `differs: N of M bytes, first at +0x…[, N wrong refs], instructions equal | N instructions differ[, diagnosis: …]` (port `ergebnis.kopfzeile` clause by clause) |
| `@comment` | optional, full text |
| `@evidence` | optional |
| `@analysis` | only when `analysis.knowledge_hash` ≠ current knowledge hash: `stale: knowledge changed since analysis (run decovery analyze)` |

`@runtime` and `@observed` are **not** generated in phase 1 (runtime schemas are fixed in phase 5, design 5.11
item 10); the parity check excludes them. After the header: one empty line, then the stored pseudo-C, or, when
`decompile_error` is set, `/* decompilation failed: <error> */`.

Index files: `index.md` table `| Address | Name | Size | Called by | Status | File |`, `calls.json`
`{"schema":1,"edges":[{"caller","site","callee"}]}`, `strings.md` `| Address | Text | Used by |`, `globals.md`
`| Address | Name | Reads | Writes |`, `status.json` with the counts `status` reports (Task 7).

**Interfaces:**
- Consumes: `Session` (Task 4).
- Produces:
  ```rust
  pub fn render_function(session: &Session, start: Address) -> Result<String, FacadeError>;

  pub fn write_all(session: &Session, lock: &WorkspaceLock) -> Result<OutputReport, FacadeError>;
  pub fn write_affected(session: &Session, change: &Change, lock: &WorkspaceLock) -> Result<OutputReport, FacadeError>;
  #[non_exhaustive] pub enum Change { Renamed { at: Address, old: String }, Symbol { at: Address }, Types, References }
  pub struct OutputReport { pub written: u32, pub removed: u32 }
  ```
