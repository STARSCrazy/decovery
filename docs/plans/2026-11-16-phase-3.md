# decovery phase 3 — implementation plan (revised 2026-11-16)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** decovery measures and raises agent effectiveness: every build attempt is remembered (attempt memory,
attempt archive, `history`), `decovery bench` runs an external agent driver on a suite of solved functions and
reports success rate, builds, tool calls, tokens and cost reproducibly — first on a small probe suite, then on the
full suite — long operations (including the bridge's `search`, `verify` and `diagnose --deep`) run as persistent
jobs (`job`), solved functions serve as exemplars (`show`, `find similar`) and their effect is measured by `bench`,
and a full build uses the machine.

**Architecture:** `decovery-core` gains the attempt store (append-only JSONL shards per function), the
content-addressed attempt archive, the tool-call log and the persistent job store. `decovery-facade` records
attempts in `build` (also for the candidates the bridge's `search` judges), gets the tools `history` and `job`, runs
long calls on a job runner, keeps the exemplar index in `cache/exemplars/` and adds exemplars plus the current
rebuild source to `show` and `find {what: similar}`. `decovery-diff` gains the similarity algorithms. A new crate
`decovery-bench` holds suites, the solution-free task copy (including the Decomp shadow), the driver contract, run
records and statistics; the CLI gets `decovery bench run|report|compare`. The reference driver is a Python stdlib
script around Claude Code in print mode (`tools/bench-drivers/claude_code.py`) that runs on the owner's
subscription and enforces a token limit itself; decovery never embeds a model.

**Tech Stack:** Rust stable (edition 2024), crates per ADR 0003 (no new dependency); Python ≥ 3.12 stdlib for the
reference driver and the measurement script; Claude Code CLI ≥ 2.1.325 (`claude -p`) for the reference driver.

**Spec:** `docs/design/0001-decovery-design.md` — section 4 (Attempt, Job, Verdict), 5.4 (`history`, `job`, `detail`,
`status`, `search`), 5.5 (`cache/`), 5.6 (`migrate`), 5.12 (items 1 and 2), 5.13, phase row 3 in section 7.
ADR 0007 (Decomp legacy bridge: shadow, one Decomp server per shadow, closed command map, verdicts stay
decovery's) and ADR 0008 (Decomp frozen; phase 3 before porting so later ports are measured; the Aztec C86 /
overlay target is the later test case). Decomp oracle (`Decomp/src/decomp/nachbau/`, Decomp is frozen, so these
stay stable): `versuche.py` (attempt memory, budget rule), `versuchsarchiv.py` (archive format, path rules, rename
retry), `versuchsherkunft.py` (compiler fingerprint), `vorbilder.py` (exemplar ranking); `dienst.py` methods
`_bau_merken`, `nachbau_probieren`, `_vorbilder`, `nachbau_vorbilder`, `nachbau_versuche` (find them by name; line
numbers drift).

## Decisions taken in this plan (deviations from the design are marked)

1. **Attempt memory is the phase-3 logbook.** Decomp's attempt memory (`versuche.jsonl` + archive) is ported and
   migrated. Decomp's method logbook stays inside the bridge's shadow until the search port (C6). Decomp's
   compile-result cache (`fassungen`) is decovery's object cache already.
2. **No SQLite (ADR 0003).** Attempts are append-only JSON Lines, one shard per function
   (`cache/attempts/<address-key>.jsonl`), so `history` reads only one function's lines and a migrated memory of
   tens of thousands of attempts needs no index.
3. **Exemplars (deviation, design 5.12 item 2 amended in Task 13):** the MinHash/LSH index of the design is the
   prefilter; the ranking is Decomp's (`vorbilder.py`): window coverage plus Indel similarity, shared stretches and
   twins. The feature list of the design (size class, call/global/string counts, rule ids) is dropped. The opt-in
   user-level library over the author's other workspaces moves to phase 4. Exemplars appear in `show`'s response,
   never in the generated `output/` files.
4. **Scheduler (deviation, design 5.13 amended in Task 11):** phase 3 builds persistent jobs and keeps the existing
   global job slots (`--jobs`) for runner work and rayon for CPU work. The DAG executor over units moves to the
   port of `search` (ADR 0008 step 3), its first user.
5. **Throughput criterion (deviation, needs the owner's confirmation before Task 14 ends):** "a full build keeps
   ≥ 90 % of the cores busy" cannot hold while the cold build is a few dozen compile jobs of very unequal length on
   16 logical cores: the lower bound is the longest compile plus the serial phases, not CPU ÷ cores. Phase 3
   measures and reaches instead **saturation ≥ 0.90** (while at least as many compile jobs are runnable as there
   are slots, the slots are busy) **and efficiency ≥ 0.85** (wall time ≤ lower bound ÷ 0.85, lower bound =
   max(longest job + serial phases, job CPU ÷ slots + serial phases)). The literal busy-core share is recorded too.
6. **Benchmark suites (deviation):** phase 3 uses private suites over local workspaces. The public suite from
   project-compiled Open Watcom / Turbo C fixtures needs a free compiler in CI and moves to phase 7. Suites are not
   tied to a target (C11).
7. **Reference driver:** Claude Code in print mode on the owner's subscription, isolated as in C4. The agent works
   only through decovery's MCP tools (no file, shell or web tools); it submits function sources with
   `build {variants}`; the harness takes the best identical attempt from the copy's attempt memory. A driver that
   edits `src/` itself is supported too: the final build sees its edits.
8. **Bench tool sets (C10):** `core` (default; the baseline for phase 4) or `core+legacy`.
9. **New crate `decovery-bench`** (design section 6 amended in Task 5), **ADR 0009** (bench driver contract,
   Task 6), **ADR 0010** (persistent jobs, Task 10).

## Global Constraints

- Everything English: identifiers, CLI verbs/flags, MCP tool and parameter names, file names, TOML/JSON keys, enum
  values, messages. Free texts written by people stay as they are. Decomp reports passed through by the bridge stay
  German (ADR 0007 decision 7).
- Fixed dependencies only (ADR 0003): `iced-x86`, `serde`, `toml`, `serde_json`, `clap`, `rmcp`, `tokio`,
  `tracing`, `rayon`, `blake3`, `sha2`, `thiserror`; `tempfile` for tests. No new crate dependency (no SQLite, no
  statistics or hashing crate: Wilson/Newcombe intervals, bootstrap PRNG (splitmix64), MinHash and LCS are written
  out). `unsafe_code = "forbid"` stays.
- No proprietary data in the repo: no target bytes, no private function names, addresses, sizes or hashes, no
  private suites or run records. Public tests use hand-built bytes, fake runner plugins, the bridge's fake `decomp`
  module and a fake driver. Local tests are `#[ignore = "local: …"]` and read `DECOVERY_LOCAL_WORKSPACE`,
  `DECOVERY_LOCAL_WORKSPACE_MZ`, `DECOVERY_TARGET_MZ`, `DECOVERY_TOOLCHAIN_WATCOM95`, `DECOVERY_TOOLCHAIN_TC20`,
  `DECOVERY_GOLDEN_DIR`, `DECOVERY_PYTHON`, `DECOVERY_DECOMP_PYTHON` and `DECOVERY_DECOMP_WORKSPACE`.
- Every on-disk record carries `schema = 1` (JSON: `"schema": 1`); writes are atomic (`write_atomic`) or single
  appends under a lock; unknown keys in records decovery rewrites are preserved (`#[serde(flatten)] extra`).
- Public enums/structs `#[non_exhaustive]`; serialized enum values are kebab-case ids; library code never panics
  on input data; malformed input names the file and line or byte offset.
- Verdicts are set only by decovery (design 4, ADR 0007 decision 5): a bench task is solved only by decovery's
  verdict on the copy; a Decomp finding is evidence.
- Nothing target-specific in code (C11): no branch on a target, compiler family or suite name in `decovery-bench`.
- Times on disk: RFC 3339 UTC to the second (`2026-11-17T08:15:02Z`), written by one helper `now_utc()` next to
  `today()` in `decovery-core`.
- Each task ends green on `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo test --workspace` (run without `DECOVERY_PYTHON` set; `runner_synthetic` maps an absolute Python path) and
  `python -m unittest discover -s tests` in each touched Python directory, then one commit with a conventional
  message and the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Stage files explicitly; LF
  line endings. No push.
- No task spends model tokens except Task 8 step 1, Task 9 and Task 15 step 2, and each of those only after the
  owner agreed to the limits it names.

## Review Focus

1. **A bench copy leaks the solution** — `.git/`, `output/`, `cache/handles/`, the kept object of the function's
   file, the object cache, `cache/rebuild/shrink/`, staged run directories, the linked program, the rebuild record,
   attempt shards and archive entries of the function, the exemplar entry, the tool-call log, the job store, and
   the Decomp shadow (`cache/legacy/`, which mirrors `src/`) and the Decomp source workspace it reads (its
   `nachbau/` holds the solution, its `wissen/nachbau.toml` the verdict). Expected: none of the function's original
   definition text (whitespace-normalised) and none of its compiled bytes occur in any file the copy or its legacy
   view contains or links to. Owner: Task 5 (`copy_contains_no_trace_of_the_solution`,
   `legacy_view_has_no_trace_of_the_solution`).
2. **A driver hangs, crashes or overspends** — the harness kills the driver's process tree at the wall limit,
   records `exit = "timeout"` / `"driver-error"` / `"token-limit"` / `"quota"`, evaluates the copy anyway and
   continues (on `quota`: pauses the run); MCP tools refuse further calls once a limit is spent ("limit reached:
   40 of 40 builds used"); the run stops starting tasks at the run token/cost limit. Owner: Task 6
   (`hanging_driver_is_killed_and_evaluated`, `crashing_driver_is_recorded`, `tool_calls_beyond_limit_are_refused`,
   `run_limit_stops_new_tasks`, `quota_pauses_and_resume_continues`), Task 8 (`token_limit_stops_claude`).
3. **Two writers append attempts at once** (a CLI build while an MCP job builds) — every line survives; a torn last
   line from a crash is skipped with a warning naming file and line. Owner: Task 1
   (`concurrent_appends_keep_every_line`, `torn_last_line_is_skipped`).
4. **The MCP server dies while a job runs** — on the next start the job is re-queued once from its spec (units come
   from the cache, a search from the shadow's logbook) and ends `interrupted` after a second loss; a cancelled
   build writes no records, no kept objects and no output; a cancelled search kills the Decomp subprocess and its
   server as the bridge does today and writes nothing into `src/`. Owner: Task 10
   (`cancelled_build_writes_nothing`, `cancelled_search_applies_nothing`), Task 11
   (`restart_requeues_running_job_once`).
5. **Exemplars on a fresh or changed workspace** — no identical function: `find similar` returns an empty list with
   the hint "no solved functions to compare with"; the target's sha256 changed: the index is rebuilt; a function is
   never its own exemplar; an assembler-file function is never an exemplar. Owner: Task 13
   (`empty_index_gives_hint`, `changed_target_rebuilds_index`, `function_is_not_its_own_exemplar`,
   `assembler_functions_are_not_exemplars`).

### Task 12: Similarity algorithms (diff)

**Files:**
- Create: `crates/decovery-diff/src/similar.rs`, `crates/decovery-diff/tests/similar_synthetic.rs`

**Interfaces:**
- Produces:
  ```rust
  pub fn instruction_forms(code: &[u8], bits: u32, base: u64) -> Vec<String>;   // padding dropped
  pub fn coarse_forms(code: &[u8], bits: u32, base: u64) -> Vec<String>;        // numbers → N, registers kept
  pub const WINDOW: usize = 6;  pub const HASHES: usize = 64;  pub const BANDS: usize = 16;  pub const PRESELECT: usize = 30;
  pub fn minhash(forms: &[u32]) -> [u64; HASHES];                // over WINDOW-grams; shorter sequences: one gram
  pub fn lsh_keys(sketch: &[u64; HASHES]) -> [u64; BANDS];       // 4 rows per band
  pub fn coverage(target: &[u32], candidate: &[u32]) -> f64;     // Decomp abdeckung
  pub fn indel_similarity(a: &[u32], b: &[u32]) -> f64;          // 2·LCS / (|a|+|b|), 1.0 for two empty
  pub fn shared_stretches(target: &[u32], candidate: &[u32]) -> Vec<Stretch>;   // top 3, longest first
  #[non_exhaustive] pub struct Stretch { pub target: (usize, usize), pub candidate: (usize, usize) }
  #[non_exhaustive] pub struct Ranked { pub candidate: usize, pub similarity: f64, pub coverage: f64, pub score: f64,
      pub stretches: Vec<Stretch>, pub twin: bool }
  pub fn rank(target: &[u32], target_coarse: &[u32], candidates: &[(&[u32], &[u32])], top: usize) -> Vec<Ranked>;
  ```
- Normalisation (port of `vorbilder.py`, on the Intel text of `decovery-diff`'s existing instruction decoding over
  iced-x86, `instructions.rs`): mnemonic + operands; hex and decimal numbers → `N`;
  `eax|ebx|ecx|edx|esi|edi` → `r`, `ax|bx|cx|dx|si|di` → `r16`, `al|ah|bl|bh|cl|ch|dl|dh` → `r8`; `ebp`, `esp`, `bp`,
  `sp` kept. `bits` 16 and 32 both work (the second target and the later 16-bit overlay target). Forms are interned
  to `u32` by the caller (Task 13 keeps the table).
- `coverage`: n = min(WINDOW, |target|); target windows = all n-grams; covered target positions are those inside any
  window that also occurs in the candidate; result = covered ÷ (windows + n − 1); 0 when the candidate is shorter than
  n. `rank`: preselect by (coverage, −|len difference|) descending, keep `max(PRESELECT, top)`, then
  `similarity = indel_similarity` rounded to 3 decimals, `score = (similarity + coverage) / 2`, descending, ties by
  candidate index; `twin` = coarse sequences equal. Stretches as Decomp `_strecken` (greedy from the front, longest
  continuation among candidate positions starting the same window).
- MinHash: hash i of a gram = splitmix64(gram_hash ⊕ seed_i), seeds = splitmix64 sequence from 0x6465636f76657279;
  gram_hash = blake3 of the gram's u32 values (first 8 bytes).
